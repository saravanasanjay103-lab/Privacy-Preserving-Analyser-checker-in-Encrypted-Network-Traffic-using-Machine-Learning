About this project

A privacy-preserving, explainable intrusion detection system built on flow metadata alone - never packet payloads.

Pipeline

  1. 1. Raw captureCICIDS2017 CSV exports ({{ '{:,}'.format(audit.rows_read) if audit.rows_read else 'full dataset' }} rows read).
  2. 2. CleaningMalformed rows and headers-in-data removed, leaving {{ '{:,}'.format(audit.rows_written) if audit.rows_written else '' }} valid flows.
  3. 3. Feature reductionEvery flow reduced to 6 metadata fields: packet count, average packet size, duration, byte rate, and inter-arrival mean/std - no payload is ever read.
  4. 4. Model trainingA Random Forest classifier learns Normal vs. Threat from the 6 features on a stratified 75/25 split.
  5. 5. Explanation{{ 'SHAP' if m.importance else 'A' }} explainer attributes each verdict back to the input features so every alert comes with a reason, not just a label.

Limitations

  • Metadata-only design cannot see payload content, so it trades some detection power for privacy.
  • Trained on CICIDS2017; behaviour on live traffic from a different network will differ.
  • {{ m.confusion.fp if m.confusion else '~600' }} false alarms in the holdout set - see Model Metrics to tune the threshold.
  • Padding, jitter and throttling can lower detection confidence - see the Evasion Lab.

Why explainability matters here

A black-box "Threat" label is hard to act on. This system pairs every verdict with the feature values that drove it and how they compare with class averages, so an analyst can judge whether to trust an alert instead of taking it on faith.
